# 訂單接 Google Sheet — 部署步驟

網站的「結帳」表單會把訂單送到一支 Google Apps Script（GAS）Web App，
由它驗證後寫進你的 Google 試算表。這支腳本要「綁定」在試算表上，需要
你手動建立與部署一次（Google 不開放用程式自動幫你做這件事）。全程約
10 分鐘，跟著做就好。

## 這是什麼、不是什麼

- ✅ 顧客送出訂單 → 你的 Google 試算表自動多一列。
- ✅ 金額由後端依商品價格表重新計算，不接受前端竄改的價格。
- ❌ **沒有串金流**，網站本身也還沒有信用卡付款欄位——這套仍然是「線上
  送出訂單，付款請於取餐/取貨時完成」的模式。
- ❌ 這不是銀行等級的安全機制。Web App 網址部署後是公開的，任何人知道
  網址理論上都能送資料進來；我們用一組共用密鑰做基本防護，擋掉不知情
  亂打網址的機器人，但擋不住存心針對你的攻擊者。這個風險等級適合「接單
  通知」，不適合拿來收集信用卡卡號等敏感資料。

## 步驟

### 1. 建立 Google 試算表

1. 前往 [sheets.google.com](https://sheets.google.com)，建立一份新試算表。
2. 幫它取個名字，例如「餃木 GYOZA WOOD 訂單」。
3. 不用手動建立分頁或欄位，稍後第一次收到訂單時腳本會自動建立
   `Orders` 分頁與標題列。

### 2. 貼上 Apps Script 程式碼

1. 在試算表上方選單點 **擴充功能 → Apps Script**，會開一個新分頁的
   程式碼編輯器。
2. 把編輯器裡預設的 `function myFunction() {...}` 全部刪掉。
3. 打開這個資料夾裡的 [`Code.gs`](./Code.gs)，複製全部內容，貼到
   Apps Script 編輯器裡。
4. 左上角把專案命名為例如「餃木訂單後端」，按儲存（磁片圖示或
   `Ctrl/Cmd+S`）。

### 3.（建議）設定專屬密鑰

`Code.gs` 裡已經內建一組密鑰 `di-pU3LwVsB7fq_FDIZMRkIijjpetFSL`，
與 `index.html` 裡的 `ORDER_SHARED_SECRET` 是配對好的，**不做這步也能動**。
如果想換一組自己的：

1. Apps Script 編輯器左側點 **專案設定**（齒輪圖示）。
2. 捲到「指令碼屬性」，點 **新增指令碼屬性**。
3. 屬性名稱填 `ORDER_SECRET`，值填一組你自訂的長亂碼字串，儲存。
4. 記得同步把 `index.html` 裡 `ORDER_SHARED_SECRET` 的值改成同一組
   （見下方「回到網站專案」）。

### 4. 部署成 Web App

1. Apps Script 編輯器右上角點 **部署 → 新增部署作業**。
2. 類型選 **網頁應用程式**（Web app）。
3. 「執行身分」選 **我**（你的帳號）。
4. 「具有應用程式存取權的使用者」選 **所有人**（Anyone）——這樣網站
   才能從瀏覽器呼叫得到；沒有登入 Google 的訪客也要能送出訂單。
5. 點 **部署**。
6. 會跳出 Google 的授權畫面（因為這是你自己寫的腳本，Google 還沒替它
   做過驗證，屬正常流程）：選擇你的帳號 → 出現「Google 尚未驗證這個應用程式」
   → 點左下角 **進階** → 點 **前往「餃木訂單後端」(不安全)** → 點
   **允許**。
7. 部署完成後會顯示一個 **網頁應用程式網址**，長得像：
   `https://script.google.com/macros/s/AKfycb.../exec`
   複製它，下一步會用到。

### 5. 回到網站專案，填入網址

打開 repo 裡的 `index.html`，找到 `<script>` 開頭附近的：

```js
const ORDER_ENDPOINT = 'PASTE_YOUR_GAS_WEB_APP_URL_HERE';
const ORDER_SHARED_SECRET = 'di-pU3LwVsB7fq_FDIZMRkIijjpetFSL';
```

把 `ORDER_ENDPOINT` 換成你剛剛複製的網址（結尾要是 `/exec`）。如果第 3
步有換過自己的密鑰，`ORDER_SHARED_SECRET` 也要改成一樣的值。存檔、
commit、push（或請 Claude 幫你）。

### 6. 測試

1. 開網站，加幾樣商品到購物車，走到結帳，填完表單送出。
2. 回到 Google 試算表，應該會看到多一個 `Orders` 分頁，裡面多了一列
   剛剛送出的測試訂單。
3. 也可以在 Apps Script 編輯器裡，函式下拉選單選
   `testHandleOrder`，按執行，不透過網頁直接測試腳本邏輯是否正常
   （會在 Orders 分頁寫入一列「測試訂單」，測完可以手動刪掉那一列）。

## 之後修改商品或改程式碼

- **網站加/刪商品、改價格**：`index.html` 的 `products` 陣列改了以後，
  記得同步更新 `Code.gs` 裡的 `PRICES` 物件（id、name、price 要一致），
  不然新商品送出會被後端擋掉（「購物車內容不正確」）。
- **改了 `Code.gs` 的邏輯**：存檔後，網址不會自動生效新程式碼——要回到
  **部署 → 管理部署作業**，點現有部署旁的鉛筆圖示，版本選
  **新版本**，再點 **部署**，網址不變但邏輯會更新。

## Orders 分頁欄位說明

| 欄位 | 說明 |
| --- | --- |
| 時間 | 伺服器收到訂單的時間（Apps Script 執行當下） |
| 訂單編號 | 伺服器產生，格式 `GW` + 年月日 + 4 碼亂數 |
| 取餐方式 | 外帶／內用／宅配 |
| 姓名／手機／Email／地址／備註 | 顧客填寫的內容 |
| 品項 | 人類可讀的品項摘要，例如「招牌爆汁鍋貼 x2, 老派酸辣湯 x1」 |
| 小計／服務費／總計 | 伺服器依價格表重新計算，非前端送來的數字 |
| 品項明細(JSON) | 原始 `[{id, qty}, ...]`，方便之後寫程式重新解析 |
| 狀態 | 預設「新訂單」，店家可自行手動改成「已完成」「已取消」等 |
| 來源 | 送出當下的網頁網址，方便除錯 |
